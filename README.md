# chat

The chat protocol. Chat services (providers) and the receiving side are separate services that reach each
other over HTTP with JSON bodies; two crates are the two ends of that wire, and a third is the protocol's
harness plugin.

| Crate | Directory | Imported or run by | Supplies |
|---|---|---|---|
| `bmo-chat` | `provider/` | a chat service | the chat piece types, the provider contract, the server for the provider routes and the link to the receiving side |
| `bmo-chat-client` | `client/` | the receiving side, and the plugin | one client for every provider, and the server for the routes a provider hands messages to |
| `bmo-chat-plugin` | `plugin/` | a coding harness | the `bmo-chat` command, whose `mcp` verb serves the harness tools over MCP for any provider, the `ahas-chat` skill, and the OpenAPI documents |

Neither library depends on the other. Each states the wire shapes on its own, and the root package's tests
check that the two agree. The plugin depends on bmo-chat-client alone.

## Documents

- `docs/contract.md`: the piece types, such as messages, sends, refusals, dialects and the provider's
  declaration.
- `docs/protocol.md`: the routes in both directions, their bodies and answers, the error codes, the retry
  rule, and the harness plugin's tools.
- `docs/openapi/provider.json`, `docs/openapi/receiver.json`: the same routes as OpenAPI 3.1 documents, one for
  each side, generated by bmo-chat-plugin, for a service written in another language. The provider document
  carries the harness tools under `x-tools`.
- `docs/conventions.md`: the common wire format, the API design and the upstream and downstream rules every
  bmo-next repository follows.
- `docs/PERSONAL-DATA.md`: what personal data never goes into the repository, and the check that reads every
  file for it.

## The harness plugin

`bmo-chat mcp --provider <url>` starts the MCP server on standard input and output, with the provider's token
in `BMO_CHAT_TOKEN` or `--token`. The skill is `plugin/skills/ahas-chat/SKILL.md`.

## Layout

- `provider/`, `client/`, `plugin/`: the three crates, each with its own `src/` and `tests/`.
- `tests/`: checks that span the repository, run as the root package's tests.
- `deploy.toml`: the build and test commands. Its format is provisional until bmo-testbed defines the
  convention; the repository holds libraries and a command run by a harness, and has no deploy command.
