# Working in this repository

This repository holds the chat protocol: its two base libraries, `bmo-chat` in `provider/`, which a chat
service imports to be a provider, and `bmo-chat-client` in `client/`, which the receiving side imports; and its
harness plugin, `bmo-chat-plugin` in `plugin/`, which builds the `bmo-chat` command and holds the `bmo-chat`
skill. It holds chat piece types, the routes that carry them and the tools that drive them. Beside the protocol
it holds what every Rust unit shares: `docs/conventions.md`, `shared-versions.toml`, the console face,
`bmo-console-face` in `console-face/`, which a unit that brings a console screen imports to serve it, and the
secret shapes, `bmo-secret-shapes` in `secret-shapes/`, which a unit that keeps or forwards words imports to
take a secret's runs out of them. It holds nothing else: no turn templates or their assembly, no jobs, memory,
agents, gates or archive.

## Rules

- **`docs/` is canonical.** `docs/contract.md` states the piece types, `docs/protocol.md` the routes and
  the plugin's tools, `docs/presence.md` the design of presence and typing across the chat services, the
  receiving side and the console, which the two before it take in as the libraries carry it, and
  `docs/console-face.md` what the console face takes and answers, `docs/secret-shapes.md` the secret shapes and
  their reading; bmo-ui's
  `docs/console-bundles.md` is the console contract it keeps, named and never restated. Read the one covering
  a change first. A change that would make it wrong repairs the document first, stating what is true now, and
  the code is then written to match. `docs/openapi/` is generated by bmo-chat-plugin and never edited by hand;
  `docs/protocol.md` names the command that writes it.
- **`docs/conventions.md` is the one source of the common wire format and the upstream and downstream rules**
  for every bmo repository: keys, times, identifiers, errors, lists, how a service's document and client
  are shaped, the order upstreams are fixed in, and a Rust unit's build profiles, test layout and shared
  registry crates. A rule of that kind is stated there, never restated here or in another repository's
  documents, which point to it.
- **The base libraries depend on nothing `bmo-*`, not even each other.** Each defines the wire shapes it
  needs on its own; the parity test at the root checks that the two sides agree. Each crate's
  `tests/dependencies.rs` fails on a `bmo-*` dependency, the console face's and the secret shapes' among them. The plugin depends on
  `bmo-chat-client` alone, and its own `tests/dependencies.rs` fails on any other.
- **The console face's tests read bmo-ui's pinned release,** the packed file `shared-versions.toml` pins, from
  the bmo-ui checkout beside this one, through Bun. That is a file they read, never a dependency of a crate.
- **The protocol knows nothing of who uses it.** No route, field, tool, document or skill names an agent, a
  worker, the receiving unit or any other unit's own concept; rooms, messages, people and the account's owner
  are the chat domain's own nouns. The console face names only the console contract's own nouns, and no unit
  that serves one.
- **Tests live in `tests/`.** A crate's tests are in its own `tests/`; checks that span the crates are in the
  root `tests/`, which belongs to the root package. No test module sits in `src/`.
- **English only** in code, comments, strings, tests and documents, and in commit messages. Messages a
  service shows are English sentences; machine-read outcomes are status codes and kebab-case codes.
- **No names of agents, owners or hosts, and no personal paths** in code, documents or commits. Write the
  role instead: the receiving side, a provider, the owner.
- **No directory named after its parent** (no `x/x`). The root `tests/layout.rs` fails on one.
- **Only Cargo manifests at the root.** The root `Cargo.toml` is the workspace and also the root package,
  which is never published and exists to hold the root `tests/`. No other build tool's manifest goes
  anywhere at the root.
- **Documents state what is true now**: no change history, no quoted source and no file-and-line pins.

## A change from a repository below

A repository below that needs a change this repository does not serve sends it as a pull request against
this repository's GitHub repository, from a branch made from this repository's main. Its job never commits
to this main and keeps no copy of the change. The change is the general case that `docs/conventions.md`
states, with this repository's own tests; before it is opened and again in review it is held to that rule.

Whoever holds this repository's work reviews the pull request and merges it or sends it back with the reason
on it; `bmo-review` may assist. A merge moves no version (`docs/conventions.md` in bmo-chat, 「Versions」: a version moves only at a release the owner declares); the repository that asked builds against the merged main through its path dependency and resumes the part it stopped.

## Checks

- Static: `cargo check --workspace --all-targets`, then `cargo clippy --workspace --all-targets` and
  `cargo fmt --all --check` (108 columns, 2-space indentation, as `rustfmt.toml` sets).
- Tests: `cargo test --workspace`, the command `testbed.toml` declares.
- The version is the set's, read off the git tags at build time (`docs/conventions.md`, 「Versions」); the
  workspace's manifest version is a placeholder that never moves.
